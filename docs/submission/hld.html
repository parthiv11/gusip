GUSIP High-Level Design / Architecture

Gujarat Unified Surveillance Intelligence Platform — hybrid overlay: Model 1 CCTV registry and GIS (mandatory) + Model 2 unified viewing and selective analytics + Model 3 VMS federation/middleware. Not Model 4 (no replacement of departmental VMS, no central 24×7 video store).

1. Problem

Gujarat’s CCTV estate is departmental and heterogeneous. The force needs statewide watchlists, multi-camera tracking, and one control-room picture without ripping out existing NVRs.

2. Principles

  1. Do not break source operations. Adapters are read-oriented.
  2. Centralise intelligence, not video. Metadata, events, embeddings, alerts, short clips only.
  3. Federation before replacement (RTSP, ONVIF Profile S/T, vendor SDKs, Sentinel evaluation API).
  4. Zero-trust internally; every query audited; purpose required on Investigate.
  5. Horizontal workers: ingest, inference, tracking, matching scale independently.

3. Logical architecture

Departmental VMS / NVR / Sentinel
        |  RTSP / ONVIF / vendor API / official live-feed API (read-only)
Ingestion / Adapter Layer
        |  sampled frames + camera telemetry

        |  JWT RBAC, protocol translation, Redis/Kafka event bus

        |  wall · ANPR · track · watchlist · alerts · search · GIS

6. Key flows

Watchlist hit: adapter samples → detect/OCR → bus → match (coalesce same camera+list) → WebSocket → wall auto-focus → ack + audit. Target < 8 s on PoC corridor.

Investigate: purpose required → events/plate route → GIS polyline → case export (role-gated).

Outage: one VMS unreachable → those cameras offline; others continue; auto-reconnect.

7. PoC scope

50 own/demo cameras (rtsp/onvif/vendor_api) across Gujarat cities; 31 official Sentinel cameras; stolen corridor Ahmedabad→Gandhinagar; RBAC, audit, case export; documented 80k scale-out. Live VAHAN/SARTHI/eGujCop/AFIS are stubs only.
